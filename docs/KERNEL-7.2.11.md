# T2 7.2.11 migration — November 8, 2026

Installed `linux-t2` and `linux-t2-headers` **7.2.11.arch1-1**, plus local
`mbp161-kernel-fixes` **7.2.11.arch1.1-1**. The kernel release and default
build target are `7.2.11-arch1-Watanare-T2-1-t2`.

## Scope

- 0001: Falcon firmware support and UCLK initialization.
- 0002: T2 NCM data-interface sleep lifecycle.
- 0004: Apple USB-C AV adapter display-mode fix.
- Packaged T2 BCE and Apple GMUX drivers retained.
- 0003 S4 reconstruction and 0005 hybrid/runtime PM excluded.
- `amdgpu.apple_falcon=1 nohibernate` retained along with the working root,
  encryption, IOMMU and sleep parameters.

Omarchy uses the existing `arch-mact2` packages, not an Omarchy T2 fork.
The [7.2.11 recipe](https://github.com/NoaHimesaka1873/linux-t2-arch/blob/v7.2.11.arch1/PKGBUILD)
pins T2 patches at `e16720782ee30fac38486b6c58d32443899c136a`. Compared with
the previous `13e7e17` pin, this includes audio suspend preparation/order and
cleanup changes, Touch Bar reset-resume handling, and an APFS update.

## Verification completed

- Kernel/header package hashes matched the configured repository metadata.
- Kernel source and Arch patch hashes matched the release recipe; all Arch,
  pinned T2 and selected local patches applied with `--fuzz=0`.
- AMD and NCM built against extracted matching headers before installation.
- `depmod -e -E Module.symvers` reported no missing symbols or CRC mismatches.
- The package dependency pins the exact `linux-t2=7.2.11.arch1-1` version.
- Both the staged UKI and the image generated by normal pacman/Limine hooks

- The normal Omarchy/linux-t2 entry remains the default. No test entry was

  verification.

## First boot and remaining validation

Boot `f8f85ccb-dcf6-4f57-a9f6-28af457fe35e` runs 7.2.11 with the expected
AMD/NCM srcversions, Falcon enabled, successful UCLK rule initialization and
successful SMU initialization. The internal panel runs at 3072x1920@60.
The user confirmed normal screen, keyboard, trackpad and speaker audio.
No failed system/user units, desktop configuration errors, GPU reset/ring
timeout or crash events were found in the checks. The prior Plymouth crash
did not recur on this boot; that does not establish a fix for it.

Two deep/S3 suspend-resume cycles completed in this boot. Journal entry-to-exit
intervals were approximately 29 seconds and 6 hours 20 minutes. Both cycles
show successful Falcon UCLK/SMU initialization, BCE stateful resume and NCM
alternate restoration. The updated audio prepare callback completed before
the VHCI suspend callback. The user confirmed normal unlocking, keyboard,
trackpad and speaker audio after the latest wake. The internal display and
audio sinks are present, with no failed system/user units or desktop config
errors. The Thunderbolt xHCI controllers still log reinitialization on wake.

External-display behavior and long-term/repeated-boot reliability remain
unvalidated. These results use our patches and do not justify removing them.
Local `post-reboot.json`, `post-reboot-kernel.log` and
`suspend-validation.log` record the checks.

The patched 7.2.9 baseline passed one deep-sleep/unlock cycle on Omarchy 4.5,
with the user confirming keyboard, trackpad and speaker audio. Plymouth
crashed while terminating the boot splash on that boot; no core was stored.
That remains a separate unresolved observation.
